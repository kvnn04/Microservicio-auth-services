1. Flujo de Registro (Sign Up)
• Registro clásico con credenciales: Creación de cuenta mediante correo electrónico y contraseña con validaciones estrictas de formato y seguridad.
• Verificación de identidad obligatoria: Envío automático y validación de códigos de un solo uso (OTP) o enlaces mágicos por email antes de activar la cuenta.
• Validación de unicidad en tiempo real: Comprobación instantánea de que el correo electrónico no esté registrado previamente.
• Registro federado (Social Auth / OAuth2): Creación de cuenta simplificada utilizando proveedores externos (Google, Apple, Microsoft, GitHub).
• Aceptación de términos y políticas: Registro obligatorio del consentimiento explícito del usuario a los términos de servicio y políticas de privacidad (esencial para normativas como GDPR).
2. Flujo de Inicio de Sesión (Sign In)
• Autenticación estándar: Validación segura de credenciales contra la base de datos (PostgreSQL) usando hashing avanzado.
• Autenticación multifactor (MFA/2FA): Segundo paso de verificación mediante aplicaciones autenticadoras (TOTP como Google Authenticator) o SMS/Email.
• Emisión y gestión de tokens: Generación del par de tokens empresariales: un Access Token (JWT de corta duración) y un Refresh Token (almacenado de forma segura).
• Inicio de sesión sin contraseña (Passwordless): Acceso directo mediante un enlace temporal enviado al correo electrónico o un código OTP.
3. Recuperación y Gestión de Credenciales
• Recuperación de contraseña (Olvidé mi contraseña): Flujo seguro que genera un token de un solo uso con expiración corta (ej. 10 minutos) enviado por correo para restablecer la clave.
• Cambio de contraseña desde la sesión: Actualización de la contraseña requiriendo la clave actual como medida de seguridad adicional.
• Cambio o actualización de correo electrónico: Modificación del email principal que requiere verificar el nuevo correo antes de hacer el cambio efectivo.
4. Control y Gestión de Sesiones
• Cierre de sesión único (Logout): Invalidación inmediata del Refresh Token actual en la base de datos o lista negra de Redis.
• Cierre de sesión global (Log out de todos los dispositivos): Revocación masiva de todos los Refresh Tokens activos asociados al ID del usuario (útil si sospecha que lo hackearon).
• Listado de sesiones activas: Consulta enterprise donde el usuario puede ver los dispositivos, navegadores, direcciones IP y ubicaciones aproximadas donde tiene su sesión abierta.
• Renovación automática de sesión (Token Refresh): Endpoint transparente para el frontend que emite un nuevo Access Token válido utilizando el Refresh Token de la Cookie HttpOnly.
5. Seguridad Proactiva y Defensa (Enterprise)
• Bloqueo de cuenta por intentos fallidos: Suspensión temporal de la cuenta tras N intentos erróneos para mitigar ataques de fuerza bruta.
• Control de tasa de peticiones (Rate Limiting): Límite máximo de peticiones por minuto por dirección IP o por cuenta (gestionado en Redis).
• Detección de comportamiento anómalo: Bloqueo preventivo o exigencia de MFA si se detecta un inicio de sesión desde un país o dispositivo completamente inusual.
• Historial y logs de auditoría (Audit Trail): Registro asincrónico (vía colas) de cada evento crítico (registro, login fallido, cambio de clave, IP de origen) para auditorías de cumplimiento legal.
